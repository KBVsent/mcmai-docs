カスタムデータソースは、ほかの入手元のスコアを取り込むための機能です。たとえば、ほかのツールから書き出し、標準形式に変換したスコアが対象です。中国版・日本版・国際版にはそれぞれカスタムデータソースのアカウントが 1 つずつあり、その地域のほかのアカウントと同じく、`/カード選択` または連携ページのアカウント一覧で切り替えられます。

::: info ご利用の前に
- **スコアのみを受け付けます。** プレイヤー情報とプレイ履歴は含まれません。Rating は McMai がスコアと譜面定数から計算し直します。
- **全体を置き換えます。** アップロードのたびに、そのアカウントのスコアがすべて置き換わり、ファイルにない譜面は削除されます。空のリストをアップロードするとスコアが消去されます。
- **ランキング。** 全体ランキングには反映されません。`/グルラン`、`/グループレート` のサーバー引数に `all` を指定した場合は反映され、データ元が表示されます。
- **標準形式のみを受け付けます。** McMai はほかのスコア管理サービスやツールの書き出しファイルを変換しません。アップロード前に[標準形式](#format)への変換が必要です。
:::

## 1. Web アップロード {#web}

1. Bot に `/連携` を送り、返された連携リンクを開きます。
2. スコアの地域のタブを選び、更新方法を「カスタム」に切り替えます。
3. スコアファイル（JSON、2 MiB 以下）を選択します。ドラッグ＆ドロップでも追加できます。
4. アップロード後すぐに McMai でこのスコアを確認したい場合は、「アップロード後、McMai をカスタムデータソースのアカウントに切り替える」にチェックを入れます。
5. 「スコアをアップロード」をクリックし、処理の完了を待ちます。

結果画面には、書き込まれた譜面数と書き込まれなかった行が表示されます。書き込みに成功し、スコアがある場合は B50 画像が生成されます。ファイルの `catalog` は選択中のタブと一致している必要があり、一致しない場合はファイル全体が受け付けられません。アップロードの間隔は 60 秒以上必要です（[制限とエラーコード](#limits)）。

## 2. 標準形式 {#format}

標準形式は 1 つの JSON オブジェクトで、`format` は `mcmai-scores` で固定です。

```json
{
  "format": "mcmai-scores",
  "version": 1,
  "catalog": "jp",
  "exported_at": "2026-11-19T08:30:00Z",
  "scores": [
    {"title": "Link(COF)", "type": "standard", "level_index": 3,
     "achievements": 100.5123, "dx_score": 1700, "fc": "ap", "fs": "fsp", "play_count": 12},
    {"title": "[宴]Wonderland Wars　オープニング", "type": "utage", "level_index": 0, "level": "14",
     "achievements": 101.0, "dx_score": 1500}
  ]
}
```

### トップレベルのフィールド {#top-level}

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `format` | はい | `mcmai-scores` で固定 |
| `version` | はい | 整数 `1` |
| `catalog` | はい | `cn`、`jp`、`intl`。曲名をどの地域の楽曲データで識別するか、どの地域のアカウントに書き込むかを決めます |
| `exported_at` | いいえ | スコアの書き出し日時。ISO 8601 形式でタイムゾーンが必要です（例：`2026-11-19T08:30:00Z`）。スコアの更新日時として使われ、省略した場合やアップロード日時より後の場合はアップロード日時になります |
| `scores` | はい | スコアの配列。最大 8000 件 |

表にないキーは無視されます。

### スコアのフィールド {#scores}

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `title` | いずれか一方 | 曲名。最大 256 文字 |
| `type` | `title` を使う場合 | `standard`、`dx`、`utage`。大文字と小文字は区別しません。`sd`、`std` は `standard` として扱います |
| `song_id` | いずれか一方 | 公式の楽曲番号。同じ曲の DX 譜面の番号はスタンダード譜面より 10000 大きく、宴譜面は 6 桁です |
| `level_index` | はい | 難易度。0 から 4 が順に Basic、Advanced、Expert、Master、Re:Master です。宴譜面は 0、2 人用宴譜面の 2 人目のポジションは 1 を指定します |
| `level` | いいえ | 表示レベル（例：`14+`）。最大 8 文字。同名の宴譜面のバリエーションを区別するために使います |
| `achievements` | はい | 達成率。パーセント値で小数点以下 4 桁まで（例：`100.5123`）。範囲は 0 から 101、宴譜面は 202 まで |
| `dx_score` | はい | DX スコア。0 以上の整数 |
| `fc` | いいえ | `fc`、`fcp`、`ap`、`app`。空文字列または `null` はなしとして扱います |
| `fs` | いいえ | `sync`、`fs`、`fsp`、`fdx`、`fdxp`。`fsd`、`fsdp` も受け付けます。空文字列または `null` はなしとして扱います |
| `play_count` | いいえ | その譜面のプレイ回数。省略した場合は 0 として記録します |

`fc`、`fs` は大文字と小文字を区別します。同じファイル内で、2 つの行が同じ譜面を指すことはできません。`song_id` と `level_index` が同じ場合、または `title`、`type`、`level_index`、`level` がすべて同じ場合が該当します。

### 譜面の特定 {#locate}

各行では、次のいずれかの方法で譜面を指定します。

- **曲名**：`title` + `type` + `level_index`。必要に応じて `level` を加えます。
- **番号**：`song_id` + `level_index`。両方を書いた場合は番号が優先され、曲名は照合しません。

曲名で識別する場合：

1. まず `catalog` で指定した楽曲データから、曲名と種別が完全に一致する譜面を探します。
2. 見つからない場合は、大文字・小文字、全角・半角、余分な空白を無視してもう一度探し、結果が 1 つに絞れたときだけ採用します。たとえば `Link(CoF)` は `Link(COF)` として識別できます。
3. 同名・同種別の曲が複数ある場合は `level` で絞り込み、1 曲に絞れない場合はその行をスキップします。現在 `level` が必要なのは、`[宴]Wonderland Wars　オープニング`、`[協]青春コンプレックス` の 2 組の宴譜面だけです。宴譜面のレベル末尾の `?` はあってもなくてもかまいません。
4. 曲名が空、または空白だけの場合は、曲名が全角スペース 1 文字の曲として識別します。

::: tip 2 曲の Link
楽曲データにはスタンダード譜面の Link が 2 曲あり、ゲーム内ではどちらも `Link` と表示されます。2 曲目は `Link(COF)` と書いてください。`Link` と書いた場合、McMai は Re:Master（1 曲目にのみある）、`level`（Advanced、Expert は 2 曲でレベルが異なる）、DX スコアが 1 曲目の上限を超えているか、の順で判定します。それでも判定できない場合はその行をスキップします。`song_id` を書けばこの影響は受けません。
:::

### 検証結果 {#validation}

アップロードしたファイルは 2 段階で検証されます。

**構造の検証**では、フィールドの型、値の範囲、重複行を確認します。通過しなかった場合はファイル全体が受け付けられず、スコアは 1 件も書き込まれません。最初の 20 件の問題が一覧表示され、位置は `scores[12].achievements` のような形式で示されます。

| コード | 意味 |
| --- | --- |
| `not_object` | オブジェクトである必要があります |
| `enum` | 値が許可された範囲にありません（`format`、`catalog`、`type`、`fc`、`fs` など） |
| `datetime` | 日時の形式が正しくないか、タイムゾーンがありません |
| `required` | 必須フィールドがありません |
| `type` | 型が正しくありません（数値を文字列で書いた場合など） |
| `too_many` | `scores` が 8000 件を超えています |
| `locator` | `title` または `song_id` がありません |
| `range` | 値の範囲を超えています |
| `scaled` | 達成率が 1000 を超えています。10000 倍されている可能性があります。パーセント値で指定してください |
| `precision` | 達成率の小数点以下が 4 桁を超えています |
| `duplicate` | 前の行と同じ譜面を指しています |

**楽曲データの検証**では、問題のある行だけをスキップし、残りは通常どおり書き込みます。結果には、スキップした行数が理由ごとに表示され、最初の 10 行の位置と曲名も表示されます。

| 理由 | 意味 |
| --- | --- |
| `unknown` | 楽曲データにその曲または譜面が見つかりません |
| `ambiguous` | 同名の譜面を区別できません。`level` または `song_id` を指定してください |
| `link_ambiguous` | どちらの Link か判定できません。`Link(COF)` に書き換えるか、`song_id` を指定してください |
| `dx_over` | DX スコアがその譜面の上限（ノーツ数 × 3）を超えています。宴譜面はチェックしません |
| `ach_over` | 宴譜面以外の達成率が 101% を超えています |
| `duplicate_chart` | 複数の行が同じ譜面に対応しています。これらの行はすべて書き込まれません |

楽曲データはゲームのアップデートに合わせて更新されます。McMai が楽曲データを更新するまで新曲はスキップされるため、更新後にもう一度アップロードすると書き込まれます。

## 3. API アップロード {#api}

プログラムから定期的にアップロードする場合は、アップロードトークンを使って API を呼び出せます。連携ページを開く必要はありません。

### アップロードトークン {#token}

連携ページで、いずれかの地域の「カスタム」から「トークンを発行」をクリックします。トークンは `mcext_` で始まり、3 つの地域で共通です。アップロード内容の `catalog` に応じて、対応する地域に書き込まれます。

- トークンは発行時に一度だけ表示されます。すぐに保存してください。紛失した場合は「トークンを再発行」をクリックすると、古いトークンは直ちに無効になります。
- 「トークンを削除」すると API からアップロードできなくなります。アップロード済みのスコアは残ります。
- トークンはスコアのアップロードとアップロード結果の照会にのみ使えます。公開するコードやスクリーンショットに含めないでください。

::: warning 連携解除後の関連付け
連携ページでカスタムデータソースのアカウントを連携解除しても、トークンが有効なままであれば、次回の API アップロードでこのアカウントが再び関連付けられます。使わなくなった場合は、トークンもあわせて削除してください。
:::

### スコアのアップロード {#upload}

```
POST https://sync.moev.cc/api/v1/ext/scores
Authorization: Bearer <アップロードトークン>
Content-Type: application/json
```

リクエストボディは標準形式の JSON オブジェクトそのものです。multipart フォームやファイルアップロードは使用しません。プログラムからはメモリ上で作成したスコアをそのまま送信でき、ファイルに保存する必要はありません。

```python
import requests

doc = {"format": "mcmai-scores", "version": 1, "catalog": "jp", "scores": scores}
r = requests.post(
    "https://sync.moev.cc/api/v1/ext/scores",
    headers={"Authorization": f"Bearer {token}"},
    json=doc,
)
```

`requests` の `json=` 引数を使うと `Content-Type: application/json` が自動で設定されます。保存済みの JSON を curl で送る場合、`@scores.json` はファイルの内容をリクエストボディとして読み込む指定です。

```bash
curl -X POST https://sync.moev.cc/api/v1/ext/scores \
  -H "Authorization: Bearer $MCMAI_EXT_TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @scores.json
```

サーバーはまず構造の検証を行い、通過するとキューに入れて処理し、リクエスト内で最大 20 秒待ちます。

- 20 秒以内に処理が終わった場合：`200` を返します。内容は[結果の照会](#task)と同じで、`task_id` も含まれます。処理に失敗した場合も `200` を返し、`status` は `failed` になります。
- 結果を待ちきれなかった場合：`202` と `{"task_id": "…"}` を返します。その後、タスク ID で照会してください。

API アップロードでは、カスタムデータソースのアカウントがトークンの所有ユーザーに関連付けられますが、McMai で現在使用中の地域は切り替わりません。

### 結果の照会 {#task}

```
GET https://sync.moev.cc/api/v1/ext/tasks/<task_id>
Authorization: Bearer <アップロードトークン>
```

`status` が `pending`、`processing` の間は処理中です。数秒おいてから再度照会してください。処理が完了すると次のようになります。

```json
{
  "status": "done",
  "kind": "ext_upload",
  "server": "ext_jp",
  "result": {
    "rating_before": 15180,
    "rating_after": 15246,
    "new_records": 5,
    "bound": true,
    "written": 1203,
    "dropped": {
      "unknown": {"count": 2, "samples": [{"path": "scores[3]", "title": "曲名"}]}
    }
  }
}
```

| フィールド | 説明 |
| --- | --- |
| `written` | 書き込まれた譜面数 |
| `dropped` | 楽曲データの検証でスキップされた行。[理由](#validation)ごとにまとめられます。`samples` は最大 10 件で、`title` はファイル内の曲名です。`song_id` だけを書いた場合は `null` になります |
| `empty` | `true` の場合、そのアカウントには現在スコアがありません |
| `rating_before`、`rating_after` | アップロード前後の Rating |

処理に失敗した場合は `status` が `failed`、`error_code` が `update_failed` になります。サーバー側の処理エラーを示すため、しばらくしてから再試行してください。

### 制限とエラーコード {#limits}

- 1 人のユーザーが同時に持てる処理中のタスクは 1 つだけです。Web アップロードも含みます。
- アップロードの間隔は 60 秒以上必要です。Web アップロードと API アップロードで共通の間隔で、前回のカスタムデータソースのアップロードから数えます。
- リクエストボディは 2 MiB 以下、スコアは 8000 件以下です。

エラー時は `{"error_code": "…"}` を返します。

| ステータスコード | `error_code` | 説明 |
| --- | --- | --- |
| 400 | `ext_invalid` | 構造の検証を通過しませんでした。`errors` に最初の 20 件の問題が `{"path", "code"}` 形式で入ります。コードは[検証結果](#validation)を参照してください |
| 400 | `bad_json` | リクエストボディが JSON オブジェクトではありません |
| 401 | `bad_token` | トークンがない、形式が正しくない、再発行済み、または削除済みです |
| 404 | `not_found` | 照会したタスクが存在しないか、このトークンのユーザーがアップロードしたものではありません |
| 409 | `task_in_progress` | 処理中のタスクがあります。その `task_id` が含まれます |
| 413 | `payload_too_large` | リクエストボディが 2 MiB を超えています |
| 415 | `bad_content_type` | `Content-Type` が `application/json` ではありません |
| 429 | `too_many_requests` | 前回のアップロードから 60 秒経っていません。`retry_after` とレスポンスヘッダー `Retry-After` に待つべき秒数が入ります |
| 503 | `bind_disabled` | サービスが受け付けを一時停止しています。しばらくしてから再試行してください |
